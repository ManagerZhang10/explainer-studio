# 当前参数与参考证据

## 默认值和要求

| 项 | 值 | 性质 |
| --- | --- | --- |
| 时长 | 120–180 秒 | 实际声音时间轴，render 前抛错门禁 |
| 页面 | 1920×1080 | build_video 常量 |
| 推荐输出 | scale 0.6666666667 → 1280×720 | ffmpeg -i 验证实际值 |
| 帧率 | 30 fps | 实现常量 |
| 起稿 | 580–720 汉字 | prompt 目标及机器范围 |
| AI 声音 | edge-tts zh-CN-YunxiNeural | 远端服务 |
| rate / pitch | +10% / +0Hz | 默认值，不是实测语速 |
| 字幕 | 当前一块，分块目标 16 字符 | 词/括号可整体超长 |
| teaching 标题/说明/字幕 | 72px / 34px / 42px | 1920 页面 CSS，输出按比例缩小 |
| 图 | 2–5 短标签 nodes，真实 links | visual 横排限制 |
| reveal | cue → marks/caps → reveal_times | 无匹配降级近似 |
| 间隔 | 0.28 秒，尾卡前 0.55 秒 | 静音补齐，不是 BGM |
| 编码 | x264，threads 2，CRF 19，medium | 不代表全机线程限制 |
| 声音 | AAC 160k、48kHz | 合并 WAV 为 24kHz 单声道 |
| 并行 | 重渲染最多 2 路，同 DAY 串行 | 包含 audit |

不以汉字数推断实际时长；不强制照搬作者语速、切镜数或响度。围绕一个机制逐步展开，不为凑切镜频率打断解释。无依据不承诺渲染耗时。

## 参考清单动态统计

参考媒体与分析是项目旁外部资产，安装 skill 不会带上：
- 下载 manifest：参考视频库（`studio refs where`）下 `creators/<作者>/manifest.json`。
- 拆解：参考视频库 `analysis/<分组>/<slug>.json`，`studio refs report` 出汇总。
- 指标：该 analysis 下 `_metrics/metrics.json`；转录范围从单片记录和 `_transcripts_oai/` 核实。
- 作者报告：该 analysis 下两份作者风格报告，仅作线索，引用前核实单片证据。

此次核对（2026-10-02）的已落盘拆解为 **10 + 10 + 1**；下载 manifest 分别 14、15 条，不能算全部下载视频均已分析。21 条均有跨全时长画面抽样；长视频口播只转录首七分钟，准确镜头、语速、BGM 等不是全片核验结果，不称为“21 条实测”或“爆款”。详见项目 `analysis/参考证据审核.md` 及新增两支 JSON 的 evidence/sampling 字段。

每次使用动态读取真实 manifest，按视频 ID 去重，对照实际媒体与分析文件；分别报告“清单条数 / 可用媒体数 / 已分析数 / 本指标有效数”，记录日期。科了个喵单片若缺可追溯 manifest 记录，应先补来源，再进入需要来源核验的统计。不能把目录文件数当完整分析数。

每项统计须记分母、scope、单位和 provider。部分可lip 长片只有 first_420s 转录，片头采样不能当全片语速。全片时长与采样节奏不能混分母；极短、占位或异常转录不得进入语速统计。作者报告和 metrics 快照并非每项都已验证。

## BGM 证据边界

silencedetect、volumedetect 或 silencevolume 只能说明波形区间和响度，不能证明音乐存在或全程铺底。间隙能量可能是噪声、混响、音效或分段误差。确认 BGM 须试听并记录片段时间；不能确认则写“未确认”。

当前 pipeline 是语音和静音补齐，没有 BGM 混音 CLI。需要 BGM 须另做混音接入及来源确认，不能把静音补齐说成背景音乐，也不采用旧文档未核实的 -27 dBFS 强制目标。

## 批量、验证和索引命令的边界

在 pipeline 目录运行：
```bash
python3 run_batch.py --prepare --workers 2 --days 1 2 3
python3 audit_pages.py 1 2 3
python3 run_batch.py --workers 2 --days 1 2 3
```

省略 --days 默认 1–14，run_batch 固定 scale=2/3、workers choices=(1,2)，输入从默认 work/scripts/dayNN.json 读取，脚本 SHA256 在生产前后核对，记录 prepare_report.json/render_report.json，有失败非零退出。它不生成口播、不支持 --script/--project-dir，须先准备并审核脚本。

完成全部 14 章后：
```bash
python3 verify_delivery.py
python3 write_index.py
```

verify_delivery 无项目参数，固定课程 1–14；用 ffmpeg -i 检查时长/编码/尺寸/帧率，并用 ffmpeg 全片 decode 检查错误，记录视频和脚本 SHA256、timeline 时差（允许 0.1 秒以内）及所有 scene 有 visual，输出 work/verify.json 和 all_pass，失败退出 1。它不做人工事实或视觉审核，不依赖当前未安装的 ffprobe。

write_index 无项目参数，读取默认脚本、timeline、verify.json 和实际视频，生成 README.md/review.html；即使核验失败也可写索引，不是门禁。核验通过后再用于最终交付。参考样本数量来自实际分析文件，目录数不代替 manifest/scope 证据核验；索引还包含课程专用文案，不能当任意新项目索引工具。

独立项目目前用实际成片路径执行：
```bash
VIDEO=/absolute/project/out/day01_实际标题.mp4
ffmpeg -hide_banner -i "$VIDEO"
ffmpeg -v error -threads 1 -i "$VIDEO" -f null -
```

第一条没有输出目标，通常以非零结束并提示必须指定输出文件，这是元数据读取方式，不判定视频损坏；查看 stderr 的 Duration、Video 和 Audio。第二条须退出 0 且无 decode 错误。另比较该项目 timeline.json 的 total 与容器时长，核验 120–180 秒、1280×720、30 fps、H.264/AAC，再抽听；不把课程 verify.json 当独立项目证据。
